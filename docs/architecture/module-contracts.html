The AI boundary

process_case(request: RunRequest, emit_progress: ProgressCallback) → RunResult

INPUT · RunRequest

Versioned snapshot

  • Schema version, run ID, case ID, case version and trigger
  • Status, owner, messages and attachments
  • Facts and source references
  • Customer, booking and flight context
  • Permitted actions and financial limits
CALLBACK · ProgressUpdate

Observable progress

  • Agreed step ID
  • Started, completed or failed
  • Display-safe summary and source IDs
  • Explicit simulation flag

System 1 assigns event IDs, sequence numbers and timestamps.

OUTPUT · RunResult

Decision or failure

  • Run ID, case ID and snapshot version
  • Success: assessment + typed action
  • Failure: technical error, no action
  • Explicit simulation flag

Action IDs and version must match the run result.

Three typed business actions

Common envelope: actionId · caseId · expectedCaseVersion · runId (AI) · sources · type · payload

REQUEST_INFORMATION

Ask for evidence

Missing facts, reasons and a English customer-facing question.

  • Simulated outbound question
  • Status → WAITING_FOR_CUSTOMER
  • Current owner retained
RESOLVE

Resolve a supported case

Outcome, explanation, versioned sources, English reply and financial positions.

  • Compensation / reimbursement / goodwill
  • Integer minor units + currency
  • Status → RESOLVED after execution
HANDOFF

Prepare specialist handling

Reason code, queue, summary, facts, evidence, unresolved questions and prior attempts.

  • Concrete reason required
  • Status → WAITING_FOR_SPECIALIST
  • Missing evidence or anger alone is insufficient

Case and run models
CaseDetail extends CaseSummary
├── snapshot: CaseSnapshot
│   ├── owner: Owner
│   ├── messages: Message[]
│   ├── attachments: AttachmentRef[]
│   ├── knownFacts / context: Fact[] → SourceRef[]
│   ├── missingInformation: MissingFact[]
│   └── financialLimits: FinancialLimit[]
├── sourceReferences: SourceRef[]
├── runResults: RunResult[]
│   ├── assessment: Assessment?
│   ├── proposedAction: RequestInformation | Resolve | Handoff | null
│   └── technicalError: TechnicalError?
└── history: ProcessEvent[]

Validation is implemented; execution remains an integration task.

Pydantic checks payload structure, IDs, versions, action variants and failure consistency. System 1 still implements permission checks, atomic state transitions, idempotency, stale-result rejection and HTTP error mapping. Human takeover invalidates older AI proposals.
