    Three rules that keep the interfaces clear

    One owner for side effects

    The platform changes state, assigns owners, reserves budgets and sends. AI supplies sourced proposals; the UI submits commands.

    Every action uses a case version

    A new message or human takeover invalidates old AI work. A stale proposal triggers fresh analysis instead of an outdated response.

    Retries preserve identity

    Message keys, command keys and outbox IDs prevent duplicate cases, responses and financial actions.

    Start in parallel, integrate on one case

    Agree on the shared fixtures and types first
    Person 1 → persisted case

    Import a fixture, accept a message, expose the snapshot and execute a recorded proposal.

    Person 2 → structured result

    Run the same snapshot through live or recorded analysis; return the same Proposal shape.

    Person 3 → usable workspace

    Render fixture responses, submit a customer reply and show delivery state and handover details.
